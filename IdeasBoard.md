## New Features

- **Use a template's initial prompt for in-app launches**: The `+ New session` popover ignores `initialPrompt` today (API launches only — the field is labelled as such). For a template with no params it could run the prompt directly; with params the name prompt would also ask for the values, validated with the same regex + max length the API uses. Decide whether the prompt is opt-in per launch. `pending_review` `medium_effort`
- **Bound terminal memory across projects**: Workspace switches unmount nothing, so kept-alive xterms pile up across every workspace the user visits. Two ideas to bound it: (a) keep the PTY + its output in main but dispose the hidden project's xterm instances on switch and re-attach/replay on switch back; (b) keep today's kept-alive behaviour but cap the number of live xterms app-wide and dispose the oldest hidden one. Both need a scrollback/replay path that does not exist yet. `pending_review` `medium_effort`
- **Sort the board**: A `Sort` button in the board filter bar's controls row, beside Search and `Filter` (it was in the toolbar mockup). Lets the operator pick the card order inside each column — today it is fixed (`sortByEnteredColumn`). Decide the sort keys (time in column, name, launch time…), whether the rail follows it, and whether the choice persists. `pending_review` `medium_effort`
- **Instant name sync from claude's session records**: `~/.claude/sessions/<pid>.json` carries `name` / `nameSource` and updates within ~1 s of a hook push or `/rename`, and survives `/clear`. A watcher on that directory would rename the card at once instead of on the next prompt, and would rebind a `/clear` without waiting for a hook. Investigated 2026-09-18 (probe on claude 2.1.276); deferred in favour of keeping the next-prompt design and making it visible. Fallback stays the `UserPromptSubmit` read-back. `pending_review` `medium_effort`
- **Custom hook port, and the banner suggests it**: The hook ingest listens on a fixed port (9279, 19279 dev, 29279 drive). When another program holds it, the server-health banner (UX-05) says session status is off and the only fix it offers is closing that program. Let the operator pick the hook port in Settings (like `apiPort`), and have the `port_in_use` banner suggest changing it. A new port must reach the hook settings file handed to each spawn (`--settings`); sessions started before the change keep POSTing to the old port, so decide whether they are re-launched, left without status, or the old port stays bound until they end. The drive/e2e harness POSTs to fixed ports and would need the value too. `pending_review` `medium_effort`
- **Action feedback polish (focus, motion, keyboard, disabled reasons)**: Left out of the action-feedback spec on purpose (`docs/superpowers/specs/2026-09-29-action-feedback-design.md`, Scope → Out). Focus return when a dialog closes; initial focus in Shortcuts and Settings; keyboard access to the terminal context menu; the StartingBanner popup's Escape and outside-click; disabled buttons that give no reason (name prompt, Tags, Workspaces); Rules' broken-marker reason visible only in a `title`. Toasts are Tab-reachable from inside a dialog (there is no focus trap — inert is the trap); the focus work inherits that knowingly. `pending_review` `medium_effort`
- **macOS port (unsigned first)**: Add a `mac` job (`macos-latest`, dmg, x64 + arm64) to `.github/workflows/release.yml` beside `linux`. Mostly POSIX already (`$SHELL -l -c`, `kill(pid,0)`); the `/proc` correlation is already gated to Linux in `launchSession.ts`. Replace the scaffold `mac.extendInfo` camera/mic/Documents strings. Decide the tray/notification behaviour without KDE, and how to smoke without a display. Signing + notarization later (Apple account). Testing: a macOS VM at best. `pending_review` `medium_effort`
- **Keep the board across an app restart**: The app can be closed with sessions open; when it reopens, each previous card is back in its workspace, in the column it was last in. Today a quit archives every bound session into Past sessions (reason `archive`, `archiveBoundSessions`), and the operator reopens them one by one with Resume (`claude --resume <id>`). Decide whether cards come back as live terminals (auto-resume on start) or as parked cards that resume on open; what column a card shows before its first hook arrives (a resumed claude has not told us its status yet); and how this fits the Past sessions records and the "every exit has a reason" rule. `pending_review` `high_effort`
- **Windows port — native claude, unsigned first**: Run the native Windows `claude.exe` through ConPTY (not WSL). Needs a platform layer for the spawn (`$SHELL -l -c` has no Windows twin), the version probe, the process-alive checks (`kill(pid,0)`, `~/.claude/sessions/<pid>.json`), paths, and an `nsis` job in `release.yml`. SmartScreen warning until a code-signing cert. Testing: the operator's Windows machine. `pending_review` `large_effort`
- **e2e in CI (`xvfb-run`)**: Run the claude-free e2e specs in CI under `xvfb-run`, with a stub `claude` on PATH for the specs that launch a session. Decide which specs need the stub and which stay local-only. `pending_review` `medium_effort`
- **e2e: `/clear` rebind with real claude (local only)**: An e2e spec that runs `/clear` in a real `claude` session and asserts the card rebinds (`session.rebound`). Local only: it needs a real claude and a login. `pending_review` `medium_effort`
- **Goals: due dates and priorities**: Tasks and goals carry no date or rank today (left out of the goals spec). Decide whether a due date or priority orders the Goals sheet, shows on cards, or only on the sheet. `pending_review` `medium_effort`
- **Goals: a template per goal**: A goal starts its sessions from the goal's chosen folder and the default launch settings. A per-goal template (model, effort, folder) would be picked once on the goal. Decide how it meets a template's own workspace rule. `pending_review` `medium_effort`
- **Goals: a global setting for `mark_task_done`**: The operator chooses whether sessions may close their tasks on every launch. A global default (Settings) could preset that choice. Decide whether a per-launch choice still overrides it. `pending_review` `low_effort`
- **A resumed planner keeps its tools**: A planner resumed from Past sessions or the dead pane comes back without its goal tools (it has no goal launch). Record the goal on the past-session record so a resume re-mints the token and config like a fresh planner. `pending_review` `medium_effort`
- **Proposal version so Accept never checks a newer proposal**: Accept sends the task ids the operator saw; if the planner replaces its proposal meanwhile, Accept checks against the newer one. A proposal version or nonce on the view and on `goals:decide-proposal` would refuse the stale Accept. `pending_review` `low_effort`
- **Memory recall inside subagents**: Recall reaches only the main conversation; a subagent gets no per-prompt or at-use block. Decide whether and how it should (spec `docs/superpowers/specs/2026-11-12-memory-phase-3-design.md`, Out of scope). `pending_review` `medium_effort`
- **Memory at use for shell commands**: Recall at use answers Read, Edit, Write and NotebookEdit only; a Bash command touching a folder with saved keys gets nothing (spec `docs/superpowers/specs/2026-11-12-memory-phase-3-design.md`, Out of scope). `pending_review` `medium_effort`
- **A global /remember**: `/remember` works only inside a session the app started with recall; decide whether a save line outside a session (the board, a global key) is wanted (spec `docs/superpowers/specs/2026-11-12-memory-phase-3-design.md`, Out of scope). `pending_review` `low_effort`
- **Recall episodes and commands with a prompt**: Per-prompt recall matches specifics and facts only; episodes and commands are left out (spec `docs/superpowers/specs/2026-11-12-memory-phase-3-design.md`, Out of scope). `pending_review` `medium_effort`
- **A lower claude floor for memory recall**: Recall needs claude 2.1.323; older versions were not run with the mod, so a lower floor needs those versions probed (spec `docs/superpowers/specs/2026-11-12-memory-phase-3-design.md`, Out of scope). `pending_review` `low_effort`
- **A per-prompt token figure on the Context page**: Context → Memory lists what recall gave, not what each prompt's block cost in tokens (spec `docs/superpowers/specs/2026-11-12-memory-phase-3-design.md`, Out of scope). `pending_review` `low_effort`
- **Force a fresh memory section into a running conversation**: claude fixes the memory section per conversation window; a fresh one mid-window needs `breakPromptCache`, which costs the prompt cache and the model's thinking (spec `docs/superpowers/specs/2026-11-12-memory-phase-3-design.md`, Out of scope). `pending_review` `medium_effort`
- **Memory copies an item under a new key when Claude restates it**: An inferred add with a saved value and another key is still saved as a new item. The Memory dialog now marks the two `Same value` when the value holds an exact term and the folder and workspace match, and the operator marks one stale; stopping the save itself, or flagging a shorter value (`true`, `80`), is still open (spec `docs/superpowers/specs/2026-11-12-memory-phase-3-design.md`, Known limits). `pending_review` `medium_effort`
- **Memory rewrites a task's check from Claude's own words**: P3-R1 covers items only; a task's check and "left with" can still change from Claude restating the index (spec `docs/superpowers/specs/2026-11-12-memory-phase-3-design.md`, Known limits). `pending_review` `medium_effort`
- **A tool result that only echoes its own call's arguments is not a sighting**: When Claude writes a recalled value with its own tool call and the result shows it back (an Edit snippet, `echo` in Bash), a save takes the value as `observed`: a `none` moves the item's last-seen date and an update is kept. Recall makes this frequent, so an item can look freshly confirmed when only memory and Claude ever said it. The section now shows short values, so Claude writes them without reading them first more often. `pending_review` `medium_effort`
- **A save can write a task that restates a recalled value**: A new task's title is free text in Claude's words, so a recalled value Claude repeats can end up in it (`inferred`). The task is then listed in the next index, so the value loops back each window, and with `Save to GOALS.md` on it is written into the project file. `pending_review` `medium_effort`
- **Slow recalls that arrive together are not logged**: `mod_memory_slow` times only one handler; many recalls arriving at once (a large store) can each wait past the mod's 250 ms, so those sessions pause memory for 30 s while main logs nothing. Time the whole wait, not only the handler. `pending_review` `low_effort`
- **No ceiling on the claude version for the memory mod, and `npm run test:mod` is not a gate**: Any claude ≥ 2.1.323 gets the mod and no launch index. If a later claude renames an event, the whole hooks module fails to load and sessions get tools but no index and no rules, with `Nothing injected.` as the only sign. `test:mod` is local only and not in the gate list; run it after every claude upgrade until this is closed. `pending_review` `medium_effort`
- **Run the once-per-window memory section in a real session**: The logic that decides a window's memory section once, at its first request (P3-C28), has run only in the engine test harness, not in a real claude session on the final build. Drive it once after the next claude upgrade (the first compose asks, later ones do not, `/clear` and compaction ask again), so a change in how claude composes requests does not leave windows without an index unseen. `pending_review` `low_effort`
- **Rows under Injected name no item**: Context → Memory lists recall's blocks as identical `With a prompt` / `With a file` rows with a time, so the operator cannot tell what recall gave. Decide how to name the item without putting memory text where it must not go. `pending_review` `low_effort`
- **Default Memory model (Haiku or Sonnet)**: The default stays `Sonnet` (`DEFAULT_MEMORY_MODEL`). The build-time probe (claude 2.1.323, synthetic slices) measured Haiku at one twelfth to one eighteenth of Sonnet's cost (10 turns: $0.0026 vs $0.031; a 209,695-character slice: $0.021 vs $0.38) with 24 of 24 Haiku candidates passing the quote check (Sonnet 25 of 27), but slower (Haiku 11 to 20 s, Sonnet 6 to 8 s). Decide the default. `pending_review` `low_effort`
- **Drops of an end-of-session save are not on Context**: Context → `Memory` lists what a save dropped only while the session's card is on the board (the record lives in RAM); an end's drops have nowhere to show once the card is gone. Decide where they show (Past sessions, Memory). `pending_review` `medium_effort`
- **A value inside a cut part of a long tool result is not saved**: A tool result is cut to its first and last part before a save reads it, so a value in the cut middle is never saved. Decide whether a long result is read in more parts. `pending_review` `medium_effort`
- **Tell the checkpoint count apart from turns a background task woke**: The `Memory checkpoint` counts every `Stop` of a session, including turns a background task's notification woke, so a checkpoint can come sooner than the operator's own turns suggest. Count only the operator's turns. `pending_review` `low_effort`
- **Memory: export to a vault**: Write memory items out to a notes vault. Parked in the memory spec (`docs/superpowers/specs/2026-11-11-memory-design.md`, Out of scope). `pending_review` `medium_effort`
- **Memory: consolidation ("dreaming")**: Merge and tidy items in the background, shown as a diff the operator accepts. Spec: `docs/superpowers/specs/2026-11-11-memory-design.md` (Out of scope). `pending_review` `high_effort`
- **Memory: "may be done" flags from commits or file changes**: Flag an item or task as possibly done when the folder's commits or files change. Spec: `docs/superpowers/specs/2026-11-11-memory-design.md` (Out of scope). `pending_review` `medium_effort`
- **Memory: propose a rule-file line from a correction**: When the operator corrects claude, propose a line for an instruction file. Spec: `docs/superpowers/specs/2026-11-11-memory-design.md` (Out of scope). `pending_review` `medium_effort`
- **Memory: pull-count hints**: Show how often an item was used ("never used in 60 days") to help the operator prune. Spec: `docs/superpowers/specs/2026-11-11-memory-design.md` (Out of scope). `pending_review` `low_effort`
- **Memory: embeddings**: Search by meaning as well as by words. Spec: `docs/superpowers/specs/2026-11-11-memory-design.md` (Out of scope). `pending_review` `high_effort`
- **Memory: recovery after the app itself is killed hard**: Recover more than phase 2's catch-up does when the app is killed. Spec: `docs/superpowers/specs/2026-11-11-memory-design.md` (Out of scope). `pending_review` `medium_effort`
- **Every folder and session name for the Memory filters**: The Memory dialog's Folder and Session filters offer the values found in the newest 100 items of the page's kind in the scope (stale ones included), plus the rows already loaded, so an older value may not be offered. An endpoint that lists every folder and session name would offer them all. `pending_review` `low_effort`
- **Memory Goal and Session filters match only the one picked**: The Memory dialog's Goal and Session chips send a name, and main matches a goal by part of its name and a session by a substring, so picking `Deploy` also lists items of `Deploy staging`. Sending the id, or an exact-match flag, would list only the one picked. `pending_review` `low_effort`
- **A line diff in Memory's History**: History shows what a restore changes as a whole-text swap (the text now removed, the picked version added); a line-by-line diff would show only the lines that differ. `pending_review` `low_effort`
- **Recall misses and wrong blocks the baseline pins**: `src/main/memory/recallQuality.test.ts` pins what per-prompt recall misses today (another form of a word, a version written without its `v`, a prompt with one key word, an item that is the oldest of four sharing the prompt's words, other words for the same thing) and what it adds wrongly (a bare number that is also a saved value, two common words another item shares). Decide which to fix; the test's lists change in the same commit, with the old and new numbers. A second fixture, src/main/memory/contextIndexQuality.test.ts, pins what the section lists per context. `pending_review` `medium_effort`
- **Memory: a setting for the size of the memory section**: The section is capped at 6,000 characters (about 30 keys). A setting with a fixed list would let the operator trade tokens for more keys (spec `docs/superpowers/specs/2026-11-14-memory-context-index-design.md`, Out of scope). `pending_review` `low_effort`
- **Memory: mute a tag or template most items carry**: A tag or template that most sessions carry lists up to 6 unrelated keys. A count per workspace could stop it from being a reason (spec `docs/superpowers/specs/2026-11-14-memory-context-index-design.md`, Out of scope). `pending_review` `medium_effort`
- **Memory: task and template filters for memory_search**: The section's count lines for the task and template groups name no filter, because `memory_search` and the Memory dialog have none. `pending_review` `low_effort`
- **Memory: recent sessions chosen by context**: The section's `Recent sessions` are still chosen by folder only, not by task, goal or tags. `pending_review` `low_effort`
- **Memory: a naming rule for keys**: Saves name a key freely (`port`, `API port`), so a later session cannot tell which service it is. A naming rule in the save prompt and in `memory_save`, or "also called" words, would help both the section and recall. `pending_review` `medium_effort`
- **Memory: a secret under a harmless key shows its first 24 characters**: The section hides a value only when a secret pattern matches, it holds `<private>`, or the key holds `password`, `passwd` or `secret` anywhere or `token`, `pwd`, `api key`, `access key`, `private key` as a word part. A short secret under any other key (`authtoken`, `mypwd`, `db pass`, `passphrase`, `signing key`, `credentials`) or inside a value under a harmless key (`note = password=hunter2`) is printed. `pending_review` `low_effort`
- **Memory: a block the window refuses reruns the full selection on every prompt**: When the saved-or-changed lines would take a window past its 20,000 characters, nothing is marked told and `built` stays, so every later prompt runs `contextRows` again and gets nothing until `/clear` or a compaction. Recall's own lines sit behind the fresh ones in that block and are refused with them. `pending_review` `low_effort`
- **Memory: newly related keys past the fifth are dropped without a count**: After a context change the block sends the top 5 keys once (spec §6); the rest never come in that window and no `<n> more` line says they exist. `pending_review` `low_effort`
- **Memory: one `memory_get` with an item's short id and its whole id reads it twice**: Ids are deduped as strings, so both print a block and record a `pulled` entry. Reading once needs a ruling on what the second id answers. `pending_review` `low_effort`
- **Memory: a key recall gave outside the session's context is not corrected when it changes**: The saved-or-changed block lists only keys the section's selection lists, so a key recall gave from another folder keeps its old value in that window. `told`'s `whole` update is also untested (seen only after 500 deliveries in a window). `pending_review` `low_effort`
- **Memory: index ask costs**: An index ask reads the short-id clash set twice (`sessionIndex.ts` and recall's index handler); at use reads it once per window. The slice 1 review measured 127–130 ms for 45,000 in-scope items. `pending_review` `low_effort`
- **Memory: model-read lines that only look safe**: The outer `wrapperSafe` on a group heading, a count line and a key line guards nothing the inner `oneLine` does not already. A goal or tag name `oneLine` changed (a reminder tag, U+2028) prints a count-line filter `memory_search` will not match. The 24-character cut is by code point, so it can split a ZWJ emoji sequence. `pending_review` `low_effort`
- **Memory: the dialog's boundary takes repeated tag ids and a relative folder**: `memory:create` / `memory:edit` store `['t1','t1']` and `app` as sent; the form never sends them, selection counts tags once and a relative folder matches no session. `pending_review` `low_effort`
- **Memory: `Choose…` on the dialog's Folder field**: The Memory form offers only folders the app already knows (goals, the workspace, live sessions, saved items). A picker would allow any folder (spec `docs/superpowers/specs/2026-11-14-memory-context-index-design.md`, Out of scope). `pending_review` `low_effort`
- **Memory: an item re-placed in the dialog reaches a running conversation only at its next window**: A change of folder, goal or tags moves no date, so nothing tells a running conversation. `pending_review` `low_effort`
- **Private text Claude repeats is still read by a save**: `<private>` hides only the text between the tags. When Claude repeats that text outside them, or a tool call or result carries it without tags, a save reads it. Decide whether memory should remember what a span held for the rest of the session and cut it wherever it shows. `pending_review` `medium_effort`
- **`/remember` with a private tag answers with the secret sentence**: A `/remember` line that holds `<private>` is refused with `That looks like a secret, so it was not saved.` A sentence of its own needs a new refusal code in the `watcher-memory` mod (its pins and `npm run test:mod`). `pending_review` `low_effort`
- **Claude's own memory tools check neither secrets nor private tags**: `memory_save` and `memory_update` save what Claude hands them; only saves from the transcript, `/remember` and Commands are checked. `pending_review` `low_effort`
- **Carry a `<private>` span across Claude's text parts**: Each of Claude's text parts is cleaned alone, so text inside the tag that one reply splits over two parts is cut only in the first part. Carry the span to the next part without letting an unclosed tag (Claude writing about the tag) hide the rest of the reply and its tool calls. `pending_review` `low_effort`
- **Dismiss a `Same value` flag**: Two specifics that rightly share a value (two ports both `8080`) stay marked `Same value` for good; a dismiss needs stored state (a field on the item). `pending_review` `low_effort`
- **`Same value` across folders**: The flag compares specifics of one folder and workspace. Recall is workspace-wide and the index lists keys of folders above and below, so a value a session restates from another folder, or a copy of a global or dialog-made item, is not marked. Decide whether related folders (a parent, a child, none) should compare, against the extra false flags. `pending_review` `low_effort`
- **Remove the memory-goal cleanup**: Remove the memory-goal cleanup (`sessionGoalStart.ts`, `memoryRegroupedAt`) once the owner's packaged profile has run it (its marker is set). `pending_review` `low_effort`
- **Archive empty memory goals**: Archive memory goals with no open tasks once one workspace holds 100 memory goals. `pending_review` `medium_effort`
- **Rank touched and planned tasks in the extraction scope**: Rank a session's `touchedBy` tasks, and a planner's planned-goal tasks, with its linked ones in the extraction scope (`scopeTasksForExtract`). `pending_review` `low_effort`

## Bugs

- **An open Goals task row squeezes its title**: On the Goals sheet, a task row opened with `▾` squeezes its title to about one letter per line. `pending_review` `low_effort`
- **Escape on an open Select in Settings closes Settings**: `Select.tsx` handles Escape only in the list's keydown; focus stays on the trigger, so Escape bubbles to the dialog frame and closes the whole Settings dialog instead of the list. `pending_review` `low_effort`
- **A refused Delete stays armed, and the store-write toast's title is cut**: When the disk refuses a dialog Delete, its button stays armed (`Confirm delete`) until it loses focus, and the `store_write_failed` toast's title is cut with `…`. `pending_review` `low_effort`
- **A `|` in a saved title shifts `memory_search` columns**: `memory_search` prints its rows as `|`-separated columns, so a `|` in a saved key or title shifts the columns of that row. `pending_review` `low_effort`
- **Context's memory token figure reads about 40% low**: `memoryActivity.ts` counts characters / 4, but memory text measured about 2.5 characters per token, so `Index: <n> tokens` understates what the index costs. `pending_review` `low_effort`
- **Task titles a save writes reach a model outside `wrapperSafe`**: The goal block (`goals/goalPrompt.ts`) prints a task's title raw, so a title a save wrote can carry a `system-reminder` tag or the memory block marker into a prompt. Low risk (the title follows `- [id] ` on one line), but outside the rule every other saved text follows. `pending_review` `low_effort`
- **Both mods report a failed install as `bridge_mod`**: A failed install of either mod reports the `bridge_mod` storage problem, so the notice cannot tell which mod failed. `pending_review` `low_effort`
- **No bidi isolation for stored text**: Names and saved text are drawn with no bidi isolation, so an RTL override character in a name can flip how the date beside it reads. `pending_review` `low_effort`
- **Context on a resumed session shows the wrong index line**: With `Memory recall` off, a resumed session's Context shows the `Index:` line of the fresh launch index (`memoryLaunch.ts` records it on every spawn), though claude keeps the index of the conversation's first launch (older than phase 3). With recall on, Context reads `Nothing injected.` until the next window, though the conversation still holds its first index. Either way Context does not show what the model holds. `pending_review` `low_effort`
- **A late index answer leaves main recording an index the window does not hold**: When main answers a window's index ask after the mod's 500 ms wait, the mod has already decided the window has no section, but main records the ids and the `Index:` line. Until the next window Context shows an index the model never got, and at use withholds those keys. The mod could tell main with its next ask that the window has no section. `pending_review` `low_effort`
- **Opening a Past session drops the template's permission mode**: A resume composes `claude --resume <id>` without the template's flags, so a session started in manual mode can reopen in auto mode (or whatever the operator's claude defaults to). Store the launch flags on the record and pass them again on a resume. `pending_review` `low_effort`
- **Raw `document.querySelector` in four renderer test files**: `SessionCard.test.tsx`, `TagMenu.test.tsx`, `AttentionRail.rows.test.tsx` and `Board.test.tsx` find the portaled tag list with 17 raw queries; moving them to testing-library turns on `no-node-access` for each whole file. `pending_review` `low_effort`
- **The packaged smoke run writes into the default profile's data folder**: `npm run smoke` runs on the default profile's userData, so it leaves Chromium profile folders and `mods/` in the installed app's folder. Smoke should use its own temp data folder, as e2e does, so a gate run never touches the operator's data. `pending_review` `low_effort`
