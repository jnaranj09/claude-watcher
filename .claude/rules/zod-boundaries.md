# Rule: fail-closed Zod boundaries

```ts
// src/shared/schemas/hookEvent.ts — the ONE hook-POST adapter.
export const HookEventSchema = z
  .object({
    session_id: z.string().min(1), // identity; blank fails closed
    hook_event_name: z.string(), // NOT enum-locked
    notification_type: z.string().optional(),
    tool_name: z.string().optional(),
    last_assistant_message: z.string().optional(), // SENSITIVE — never log
    tool_input: z.unknown().optional() // SENSITIVE — never log; read only by toolDetail.ts
  })
  .passthrough() // claude additions pass; known-key malformations fail closed

const r = HookEventSchema.safeParse(JSON.parse(body))
if (!r.success) {
  const issue = r.error.issues[0]
  log({ path: issue.path.join('.'), code: issue.code }) // PATH + CODE only
  respond400()
  return
}
onHookEvent(r.data)
```

Other external input: the transcript, read by two readers through `transcriptEntry.ts`: the tail
(`hooks/transcriptSignal.ts`; bad-input test `src/main/hooks/transcriptSignal.test.ts`) and memory's reader (`memory/extract/transcriptReader.ts`, row above).
The memory settings (`memoryCheckpoint`, `memorySaveTasks`, `memoryModel`,
`memoryRecallEnabled`) are additive with defaults on v1 and parse with their file (the persisted
file read row); `settings:set` patches go through `SettingsPatchSchema`. A Past sessions record's
`memory` is never written into the record (R50): its own file (row above), merged by main on read; a record an earlier phase-2 build wrote
with the field still parses, and the load moves the field out (the record is stripped only once
the state file holds it).

**Never log the parsed value.** A `ZodError` stringifies its input (prompts, assistant text, tool
input, PTY content). Log PATH + CODE only — never `error`, never the body. Asserted by
`src/__fixtures__/fakeHookFeed.test.ts`.

**Parse once.** `hookEvent.ts`, `session.ts`, `claudeSessionFile.ts` are parse-once; never re-run a
schema over parsed output (the timestamp transform expects a string). Launch synthesis CONSTRUCTS a
valid `Session`, never re-parses.

**Past the boundary, the type is the proof.** No re-validation, no cast to force a value through.
A cast lives only inside a small, named, tested helper. Sensor: `tsc` strict + ESLint
`no-explicit-any`; casts: the per-file `as` budget (`tests/main/typeAssertions.guard.test.ts`).

**Each boundary has a test with a bad input** that shows the fail-closed result (refusal, reset
with backup, or `code=` log). Prose only (the reviewer's "Fail-closed Zod boundaries" check).

**State is a tagged union with an exhaustive match**, not a set of booleans. A forgotten case is a
compile error. Sensor: `tsc` + ESLint `switch-exhaustiveness-check`.

## Don't

- Enum-lock `status` or `hook_event_name`.
- Key/dedup by `pid` (use the stable `id`).
- Narrow `pendingToolInput` (polymorphic).
- Synthesize a session from an unknown-id hook (`hook_unknown_id` no-op).
